# Quillpad v1 → v2: a running server app, proxied (our fixture)

- **App:** Quillpad (`examples/server/`), a server-rendered Node app we wrote for this case. It has no build step and no dependencies, and it keeps the user's draft in a cookie. This is **our fixture, not an upstream bug.** It shows Returner on a running app rather than a static build.
- **The bug:** v2 stores the draft cookie as base64url JSON, but v1's cookie is URL-encoded JSON. On a v1 cookie, v2's decoder throws and the page answers `500 Internal Server Error`. Only returning users have a v1 cookie, so a test that starts with an empty profile never sees it.
- **How it ran:** `examples/server/run.sh codex`, one uninterrupted run on Nov 22, exit 0. The script starts v1. Returner starts each v2 candidate with `--start` and proxies both through its one localhost origin. Returner opens Chrome itself for every check and closes it cleanly, so the v1 cookie reaches disk (see below).
- **Before** (`before/`): the v1 baseline saved a draft with a random marker. On v2 the new user passed, and Kane's returning user got the 500 page.
- **Repair:** the agent's prompt (`prompt-1.txt`, marker redacted) carried Kane's finding, the browser console error and, new with `--start`, the app server's own stack trace (`SyntaxError … at decode (server.mjs:8)`, also in `server.log`). It also named v1's `server.mjs` as read-only reference material. Codex fixed it on attempt 1 (`repair.diff`): the decoder reads both formats, and new saves stay in the v2 format.
- **After** (`after/`): the replay from the same untouched v1 profile passed the new user, the returning user (the original draft opened, edited, saved and reloaded) and the separate read-back of the saved edit.
- **Fresh confirmation** (`fresh/`): a full rehearsal with a new marker, including a new v1 baseline, also passed all four checks. `attempt-1.json` records both runs.
- **Cookies needed a Returner fix first.** The first live run showed blank fields instead of the 500: the saved v1 profile had an empty cookies database. Chrome writes new cookies to disk in batches and on a clean shutdown, and the way Kane ended Chrome skipped that. Returner now launches Chrome, lets Kane attach over DevTools (`--cdp-endpoint`) and closes it with `Browser.close`. A second run then reached the 500 and passed its replay, but its fresh confirmation came back inconclusive (Kane read "fail immediately" as an order to stop, as on PKIMM), so Returner reported exit 2 rather than a pass. This folder is the next, clean run.
- **Paths:** absolute local paths in `prompt-1.txt`, `server.log` and `attempt-1.json` were shortened to `…/returner/` before publishing. Nothing else was edited.
