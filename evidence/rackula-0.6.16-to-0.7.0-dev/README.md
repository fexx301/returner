# Rackula v0.6.16 → v0.7.0 development build (RackulaLives/Rackula#935)

- **App:** [Rackula](https://github.com/RackulaLives/Rackula) (MIT), a rack layout designer. `examples/rackula/prepare.sh` builds pinned commits from source.
- **Scope:** the maintainers caught this regression during v0.7.0 release prep. The fix ([#940](https://github.com/RackulaLives/Rackula/pull/940)) merged 7 minutes before v0.7.0 was tagged, so no published release shipped it. The broken candidate is the commit before the fix (`223ac90`). Returner automates the kind of check that caught it.
- **Before** (`before/`): the v0.6.16 baseline created a 24U rack named with a random marker and confirmed it after reload. On the candidate the new user passed. For the returning user the canvas was empty, and Kane's console log for that session captured `Cannot read properties of undefined (reading 'map')` at the first step, on page load (`before/console-errors.ndjson`, extracted from Kane's evidence pack). Issue #935 says the same: v0.6.x autosaves hold a single `rack`, and the new code expects `racks`. Kane's written summary suggested opening a different view, but its screenshots show the same default view in which the repaired build displays the rack.
- **Repair:** `examples/rackula/run.sh codex` (attempt 1). Codex sent legacy single-rack autosaves through the existing `LayoutSchema` migration and forced position migration for that format (`repair.diff`). The upstream fix instead added a dedicated migration in `session-storage.ts` with tests. Codex added no tests.
- **After** (`after/`): the replay used the same untouched v0.6.16 profile, and the canvas shows the rack with the original marker. The test rack had no devices, so device-position migration was not exercised.
