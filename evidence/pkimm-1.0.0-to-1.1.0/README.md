# PKIMM 1.0.0 → 1.1.0 (pkic/self-assessment issue #148)

- **App:** [pkic/self-assessment](https://github.com/pkic/self-assessment) widget v1.0.3 (MIT), built from source. Model data from [pkic/pkimm @060be60](https://github.com/pkic/pkimm/tree/060be60bf6ad16a0d6fcb967ef6d06e29771bf3f/tools/self-assessment) (MIT). Reproduce with `examples/pkimm/prepare.sh`.
- **Before** (`before/`): the v1 baseline saved an assessment name, an assessor name and three answers, then verified them after reload. On model 1.1.0 the new user passed. The returning user got a blank page, and Kane's console evidence read `Cannot read properties of undefined (reading 'result')`. Issue #148 reports the same blank widget.
- **Repair:** `examples/pkimm/run.sh claude` gave Kane's finding and the 1.0.0 model (read-only) to Claude Code. Its patch (`repair.diff`) remaps the 9 category keys that changed between 1.0.0 and 1.1.0 (the other 6 kept their IDs, and Cryptography was added), fills new categories with defaults, records `modelVersion` in new saves and adds a unit test. **Uncovered case:** it treats every unversioned save as a 1.0.0 save. Users who first saved on the shipped 1.1.0 release also have unversioned saves, so for them it can overwrite an answer (for example Key management M.6 is replaced by Certificate management). The recorded replay tested 1.0.0 saves only. The Codex run's patch (`codex-recorded-run/repair.diff`) detects the 1.0.0 layout by its old-only keys instead. The mapping is specific to this one model change. Upstream's v2.0.0 later shipped a general migration.
- **After** (`after/`): the replay used the same untouched v1 profile. Kane read the Report, Governance, Management and Resources tabs without changing anything. It confirmed both names, all three answers and the new Cryptography category.
- **Disclosure:** the loop's own replay of this patch was inconclusive because Kane read "fail immediately without typing" as an instruction to stop. The check was reworded as a plain read-only rule with the same requirements (commit in this repo). The patch was then replayed with `returner --replay` from the same baseline. Earlier runs are not counted: one check was too narrow and passed a half-correct patch, and one baseline lost an answer.
- **Two-profile holdout verification (Nov 22):** [`two-profile/README.md`](two-profile/README.md) records the later two-profile runs at commit [`c752cc7`](https://github.com/fexx301/returner/commit/c752cc7f2fecc644b28cf1633320d1ea9afac87b) — both a deliberate negative-control test case (an incomplete `3 / 4 / 2` patch that passes Profile A, fails holdout Profile B on Sourcing, and is rejected with exit `1`) and a separate genuine Codex repair (passing Profile A, holdout Profile B, and a fresh rehearsal on attempt 2, exit `0`). The earlier single-profile folders above are preserved unchanged.
