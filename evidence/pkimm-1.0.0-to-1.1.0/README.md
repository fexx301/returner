# PKIMM 1.0.0 → 1.1.0 (pkic/self-assessment issue #148)

- **App:** [pkic/self-assessment](https://github.com/pkic/self-assessment) widget v1.0.3 (MIT), built from source. Model data from [pkic/pkimm @060be60](https://github.com/pkic/pkimm/tree/060be60bf6ad16a0d6fcb967ef6d06e29771bf3f/tools/self-assessment) (MIT). Reproduce with `examples/pkimm/prepare.sh`.
- **Before** (`before/`): the v1 baseline saved an assessment name, an assessor name and three answers, then verified them after reload. On model 1.1.0 the new user passed. The returning user got a blank page, and Kane's console evidence read `Cannot read properties of undefined (reading 'result')`. Issue #148 reports the same blank widget.
- **Repair:** `examples/pkimm/run.sh claude` gave Kane's finding and the 1.0.0 model (read-only) to Claude Code. Its patch (`repair.diff`) maps the 15 renumbered category keys from 1.0.0 to 1.1.0, fills new categories with defaults, records `modelVersion` in new saves and adds a unit test. The mapping is specific to this one model change. Upstream's v2.0.0 later shipped a general migration.
- **After** (`after/`): the replay used the same untouched v1 profile. Kane read the Report, Governance, Management and Resources tabs without changing anything. It confirmed both names, all three answers and the new Cryptography category.
- **Disclosure:** the loop's own replay of this patch was inconclusive because Kane read "fail immediately without typing" as an instruction to stop. The check was reworded as a plain read-only rule with the same requirements (commit in this repo). The patch was then replayed with `returner --replay` from the same baseline. Earlier runs are not counted: one check was too narrow and passed a half-correct patch, and one baseline lost an answer.
